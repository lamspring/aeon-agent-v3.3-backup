# MiMo-Driven Development — 虾虾专属技能

> **核心流程：问MIMO → 制定方案 → MiMo审查找bug → 优化方案 → 执行**
> 
> 目的：大幅度降低任务完成的bug，提升方案质量

---

## 1. 流程定义

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   问MIMO    │ → │  制定方案   │ → │  MiMo审查   │ → │  优化方案   │ → │    执行     │
│  (What)     │    │  (How)      │    │  (Review)   │    │  (Fix)      │    │  (Do)       │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
     明确目标          详细设计          发现缺陷          修复问题          安全执行
```

---

## 2. 每个阶段的具体操作

### Phase 1: 问MIMO — 明确目标

**触发条件：**
- 用户给了一个复杂任务
- 我不确定该怎么做
- 任务涉及架构设计或重要决策

**操作：**
1. 收集当前状态（已完成的、未完成的）
2. 准备简洁的问题描述（不超过2000字）
3. 调用 MiMo API，明确问：
   - "接下来最关键的一件事是什么？"
   - "为什么选这个而不是其他的？"
   - "具体的执行建议？"

**输出：**
- MiMo给出的决策方向（A/B/C/D选择）
- 核心理由
- 具体执行步骤

---

### Phase 2: 制定方案 — 详细设计

**触发条件：**
- MiMo给出了明确方向
- 需要写代码/改架构/设计模块

**操作：**
1. 阅读相关现有代码（如果有）
2. 编写详细设计方案文档，包含：
   - 总体架构图
   - 数据结构设计
   - 接口定义
   - 存储方案
   - 与现有系统集成方式
   - 文件创建计划
   - 潜在风险与缓解
   - 验收标准

**文档格式：**
```markdown
# {ModuleName} 设计方案 v1.0

## 1. 总体架构
## 2. 数据结构设计
## 3. 存储方案
## 4. 核心接口设计
## 5. 与现有系统集成
## 6. 文件创建计划
## 7. 潜在风险与缓解
## 8. 验收标准
```

**输出：**
- `DESIGN_{ModuleName}_v1.md`

---

### Phase 3: MiMo审查 — 发现缺陷

**触发条件：**
- 设计方案初稿完成
- 要开始写代码之前（必须做）

**操作：**
1. 读取设计方案文档
2. 调用 MiMo API，明确问：
   - "请审查以下设计方案，找出潜在bug、设计缺陷和优化建议"
   - "审查重点：数据结构、存储方案、接口设计、集成冲突、性能瓶颈、安全性"
3. 要求 MiMo 分类输出：
   - **严重问题**（必须修复，否则系统出错）
   - **设计缺陷**（建议改进，影响可维护性/扩展性）
   - **优化建议**（可做可不做，但能提升质量）

**输出：**
- 审查报告（保存到 `/tmp/mimo_review_{module}.txt`）

---

### Phase 4: 优化方案 — 修复问题

**触发条件：**
- MiMo审查发现了问题
- 用户说"优化"或"修改"

**操作：**
1. 读取审查报告中的"严重问题"
2. 逐条修复（修改设计方案文档）
3. 修复后更新版本号（v1 → v2）
4. 保存为 `DESIGN_{ModuleName}_v2.md`

**常见修复：**
- JSONL → SQLite（并发问题）
- 硬编码路径 → 环境变量
- 数据分类错误 → 修正映射逻辑
- 缺少安全边界 → 增加清洗层

**输出：**
- 优化后的设计方案文档

---

### Phase 5: 执行 — 安全实施

**触发条件：**
- MiMo审查通过（或用户说"可以执行"）
- 优化后的方案已就绪

**操作：**
1. 按文件创建计划逐个实现
2. 每实现一个核心文件，立即测试
3. 遇到错误立即修复（不要累积）
4. 完成后运行完整验收标准检查

**测试策略：**
- 单元测试（文件末尾的 `if __name__ == "__main__"`）
- 集成测试（与现有模块联调）
- 数据验证（迁移脚本、数据一致性）

**输出：**
- 可运行的代码
- 测试通过的日志

## 3. 使用示例

### 场景：实现一个新模块

```
用户：实现XX功能

虾虾：
1. 【问MIMO】收集当前状态 → 调用MiMo获取方向
2. 【制定方案】写 DESIGN_XX_v1.md
3. 【MiMo审查】读v1 → 调用MiMo找bug → 保存审查报告
4. 【优化方案】修复严重问题 → 写 DESIGN_XX_v2.md
5. 【执行】按v2方案实现代码 → 测试 → 集成
```

### 场景：修复现有系统

```
用户：XX功能有问题

虾虾：
1. 【问MIMO】描述问题 → 调用MiMo获取修复建议
2. 【制定方案】写修复计划（如果复杂）
3. 【MiMo审查】如果是架构级修复，让MiMo审查
4. 【优化方案】修复审查发现的问题
5. 【执行】实施修复 → 测试 → 验证
```

---

## 4. 关键原则

### 必须遵守
- **审查不通过，不执行代码**
- **严重问题必须全部修复**
- **每个文件实现后立即测试**
- **不要累积错误**

### 可调整
- 简单任务（<30分钟）可以跳过审查
- 紧急修复可以先执行，事后补审查
- 审查提示词可以根据任务类型调整

## 5. 提示词模板

### 模板A：问MIMO（方向决策）
```
你是一位资深系统架构师。请评估当前工作状态，给出下一步建议。

## 当前已完成
...

## 可选下一步
A. ...
B. ...
C. ...

请给出：
1. 当前完成度百分比
2. 下一步只选一件事（A/B/C）
3. 为什么选这个
4. 具体怎么执行

用简短bullet points回答。
```

### 模板B：MiMo审查（方案审查）
```
你是一位资深代码审查专家。请审查以下设计方案，找出潜在bug、设计缺陷和优化建议。

## 审查重点
1. 数据结构设计是否合理？
2. 存储方案是否可靠？
3. 接口设计是否完整？
4. 与现有系统集成是否有冲突？
5. 性能瓶颈？
6. 安全性？

## 设计方案
...

请给出：
1. 严重问题（必须修复）
2. 设计缺陷（建议改进）
3. 优化建议（可选）
4. 一句话总结：这个方案能否安全执行？
```

## 7. 历史验证

### 成功案例：PMNManager
- **审查前：** JSONL存储、硬编码路径、数据分类错误
- **MiMo发现：** 4个严重问题
- **修复后：** SQLite+WAL、配置化路径、修正迁移逻辑、ContextSanitizer
- **结果：** 测试通过，0错误

### 反例教训：
- 如果不审查直接执行，可能会遇到：并发写入损坏、数据污染、架构耦合过紧
- 审查投入的时间（10-20分钟）可以节省数小时的调试时间
