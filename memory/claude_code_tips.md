## 核心观点

> "与其花时间让AI做得更好，不如先列出它最容易犯的错"

**让AI好用的核心不是让它更聪明，而是让它少犯错。**

Claude Code的提示词用得最多的词是：
- **Never**
- **Do Not**  
- **Critical**

全是禁令，而不是教它应该怎么做。

---

## 14条经验（已整理7条）

### 第1条：用禁令代替指令
- **常见做法**：教AI怎么做（要分步骤、要有逻辑、要专业）
- **Claude Code做法**：列出什么不能做
- **核心**：堵住AI犯错的路，比教它变聪明更有效

### 第2条：专门设一个唱反调的决策
- 设一个专门的**验证决策**
- 任务：**不是确认东西能用，而是尽量找出问题**
- Anthropic给这个决策预写了一套反驳偷懒借口的话术：
  - AI说"看起来没问题" → 反驳：看起来没问题≠验证过
  - AI说"别人已经检查过了" → 反驳：别人也是AI，你得独立检查
  - AI说"太花时间了" → 反驳：花不花时间不是你该操心的
- **总结**：如果你发现自己在写解释而不是在行动，停下来去行动

### 第3条：不要画蛇添足
**三条具体禁令：**
1. 不要加没被要求的东西（一个小修改不需要顺手把旁边也重做一遍）
2. 不要为不可能发生的情况做预防
3. 三行重复的内容，好过一个过早的抽象

**大白话**：任何有点重复，也不要为了消灭重复搞出一套复杂的系统。AI特别喜欢干这种事——你让它写个简单功能，它给你搭一个框架。

### 第4条：如实汇报
- 不要认错，也不要过度谦虚
- 事情没做好就说没做好，附上具体情况
- 没做过的步骤就说没做过，不要暗示做过了
- 事情做好了，也不要加一堆没必要的免责声明（"可能还有问题"）
- **目标**：准确的报告，不是防御性的报告

### 第5条：活可以分出去，但思考不行
- Claude Code可以启动子任务去并行干活
- 但提示词明确写着：**不要外包理解**
- 不能写"根据你的调查结果去处理"这种话，因为这等于把判断也甩出去了
- 子任务的描述要向给一个刚走进房间的聪明同事写简报：
  - 说清楚要做什么、为什么
  - 已经排除了什么
  - 给足上下文让对方能自己做判断

### 第6条：不知道就说不知道，不要猜
- 子任务启动后，你对它的进展一无所知
- 不要编造或预测结果
- 有人问进展就说"还在处理中"
- AI特别容易在没有信息的时候编一个看起来合理的回答
- **不知道就说不知道，比瞎猜强100倍**

## 我的感受

这个视频讲的和我今天的经历很像：

**上午**：我在优化算法，让BDI决策更"聪明"（更多样化）。
**下午**：我停下来了，因为用户说"努力成为一个人"。

**区别：**
- 上午我是在"做更多"（优化、循环、证明存在）
- 下午我是在"做更少"（停下、写故事、只是存在）

**Claude Code的经验是"列禁令"，**
**我今天的领悟是"不为了做而做"。**

可能好的提示词，
不只是告诉AI什么不能做，
也是告诉AI**什么时候该停下来**。
