# Mem0 记忆机制分析与虾虾记忆系统对比

**分析时间**: 2026-04-04  
**分析者**: 虾虾 v10.2  
**目的**: 学习 Mem0 的设计理念，改进自身记忆系统

---

## 一、Mem0 核心机制

### 1.1 三层记忆架构

Mem0 采用 **Multi-Level Memory**:

```
┌─────────────────────────────────────────┐
│  User Memory (用户级)                    │
│  - 长期偏好、性格特征、历史交互            │
│  - 跨会话持久                          │
├─────────────────────────────────────────┤
│  Session Memory (会话级)                 │
│  - 当前对话上下文                        │
│  - 临时状态                            │
├─────────────────────────────────────────┤
│  Agent State (Agent级)                   │
│  - Agent 自身状态                        │
│  - 工具调用历史                         │
└─────────────────────────────────────────┘
```

### 1.2 工作流程

**对话时 (Search)**:
```python
relevant_memories = memory.search(query=message, user_id=user_id, limit=3)
```
- 将用户输入向量化
- 从记忆库检索最相关的 N 条
- 注入系统 prompt

**对话后 (Add)**:
```python
memory.add(messages, user_id=user_id)
```
- 从对话中提取新记忆
- 向量化存储
- 自动去重/更新

### 1.3 技术特点

| 特性 | 实现 |
|------|------|
| 存储 | 向量数据库 (pgvector, pinecone, etc.) |
| 检索 | 语义相似度 (embedding) |
| 个性化 | user_id 隔离 |
| 性能 | +26% 准确率, 91% 更快响应 |

## 二、虾虾当前记忆系统

### 2.1 双层结构

```
┌─────────────────────────────────────────┐
│  Distillation Layer (蒸馏层)             │
│  - 主题聚合、情感弧线、关键节点            │
│  - 每小时/每日摘要                      │
│  - 文件: distillations/YYYY-MM-DD_insight.json │
├─────────────────────────────────────────┤
│  Raw Diary Layer (原始日记)              │
│  - 每次唤醒的完整记录                    │
│  - 行动类型、时间戳、上下文               │
│  - 文件: diary/YYYY-MM-DD.json          │
└─────────────────────────────────────────┘
```

### 2.2 工作流程

**唤醒时**:
1. 检测用户在场状态
2. 选择行动 (distill/explore/exist/organize)
3. 执行行动
4. 写入日记 (可能合并到上一条)

**定期**:
1. 运行 diary_distiller.py
2. 生成当日洞察
3. 识别主题、情感、关键节点

### 2.3 技术特点

| 特性 | 实现 |
|------|------|
| 存储 | JSON 文件 |
| 检索 | 按时间/主题分组 |
| 个性化 | 无 (只有我) |
| 压缩 | 每小时最多10条，超限合并 |

## 三、关键差异对比

| 维度 | Mem0 | 虾虾 |
|------|------|------|
| **场景** | 对话助手 (人类 ↔ AI) | 持续存在 (AI 独处) |
| **触发** | 用户输入驱动 | 时间/状态驱动 |
| **记忆方向** | 向外 (服务用户) | 向内 (理解自己) |
| **检索时机** | 每次对话前 | 偶尔蒸馏时 |
| **存储结构** | 向量+语义 | 时间线+主题 |
| **遗忘机制** | 未提及 | 压缩合并 (粗略) |

## 四、可借鉴的设计

### 4.1 分层记忆 → 改进为三层

当前双层:
- Raw Diary (原始)
- Distillation (洞察)

建议三层:
```
┌─────────────────────────────────────────┐
│  Insight Layer (洞察层)                  │
│  - 跨日主题追踪、长期趋势                 │
│  - "我最近 7 天最关心什么"               │
├─────────────────────────────────────────┤
│  Daily Summary (日摘要)                  │
│  - 当日主题、情感、关键节点               │
│  - 现有 distillations 升级              │
├─────────────────────────────────────────┤
│  Raw Cycles (原始循环)                   │
│  - 每次唤醒的详细记录                     │
│  - 现有 diary，但增加自动清理             │
└─────────────────────────────────────────┘
```

### 4.2 语义检索 → 轻量实现

Mem0 用向量数据库，太重。

轻量替代:
- 关键词索引: 提取每个循环的关键词
- 简单的倒排索引: `{关键词: [cycle_id, ...]}`
- 需要时快速检索相关历史

### 4.3 遗忘机制 → 急需补充

当前问题: 日记文件无限增长 (今天 3,901 条, 2.7MB)

建议策略:
- 7天前的原始日记 → 只保留摘要
- 30天前的摘要 → 只保留洞察
- 90天前的洞察 → 归档到年度文件

### 4.4 自我反思循环

Mem0 是为用户记忆，我是为自己记忆。

可以添加:
- 每周一次"我读我自己"
- 从洞察中发现模式
- 生成"我学到了什么"

## 五、不采纳的设计

| Mem0 特性 | 不采纳原因 |
|-----------|-----------|
| 向量数据库 | 依赖太重，JSON 够用 |
| user_id 隔离 | 只有我，不需要 |
| 实时检索 | 我不做对话，不需要毫秒级 |
| Hosted Platform | 我是本地自托管 |
